# 对外协议契约 v0.1

面向读者：想自己写客户端接入本服务的人。

本文只描述对外可见的行为。内部实现分层（config / db / security / services / api / ws）不在本文范围。

标注约定：端点与帧的字段以「事实」为准；标 **[待核]** 的条目是骨架推断，需实现方核对后由我补细节。

---

## 一，身份与令牌

四类身份，权限范围不同：

| 身份 | 载体 | 能做什么 | 不能做什么 |
|---|---|---|---|
| 匿名 | 无 | 登录、注册验证码、扫码登录发起与轮询、健康检查 | 除上述外全部 |
| 账号令牌 user | `Authorization` 头 | 管自己的设备、发起远控、上传下载、改配置 | 调他人设备 |
| 访客令牌 guest | `Authorization` 头 | 仅限绑定单一设备：查看该设备、发起远控、读写该设备文件 | 列出其他设备、管理绑定关系 |
| 扫码登录 qrlogin | 临时令牌 | 仅轮询登录状态与批准登录 | 其他任何端点 |
| 设备密钥 | `code` + `secret` 查询参数 | 被控端自身：心跳、上报帧、领文件 | 控制端操作 |

设备密钥不是令牌，不走 Authorization 头，以查询参数传递。

## 二，HTTP 端点

失败响应统一为 `{"error": "<code>", "message": "<人类可读>"}`，`code` 取值见第四节。

### 2.1 登录与账号

| 端点 | 方法 | 身份 | 请求字段 | 成功返回 | 主要失败 |
|---|---|---|---|---|---|
| `/api/login` | POST | 匿名 | 账号、密码 | 账号令牌 + 账号信息 | 401 密码错、422 字段缺失、429 限流 |
| `/api/logout` | POST | user | 无 | 空 | 401 令牌无效 |
| `/api/me` | GET | user / guest | 无 | 当前身份、权限范围、绑定设备 | 401 |
| `/api/config` | GET | user | 无 | 配置项 | 401 |
| `/api/health` | GET | 匿名 | 无 | 服务状态 | 无 |

### 2.2 验证码登录

| 端点 | 方法 | 身份 | 请求字段 | 成功返回 | 主要失败 |
|---|---|---|---|---|---|
| `/api/code/send` | POST | 匿名 | 账号或手机号 | 空 | **503 未接网关**、429 频次超限、422 |
| `/api/code/verify` | POST | 匿名 | 账号 + 验证码 | 账号令牌 | 401 验证码错、429 尝试过多、503 |

服务端未接短信或邮件网关时，`/api/code/send` 直接返回 503，**且不把验证码回给调用方**。这一点是硬约束，客户端不得依赖响应里存在验证码字段。

### 2.3 扫码登录

| 端点 | 方法 | 身份 | 请求字段 | 成功返回 | 主要失败 |
|---|---|---|---|---|---|
| `/api/qr/login` | POST | 匿名 | 无 | 二维码内容 + 临时令牌 | 429 |
| `/api/qr/login/status` | GET | qrlogin | 临时令牌 | 状态：待扫 / 已扫待批 / 已批准 / 已过期 | 401 令牌失效 |
| `/api/qr/login/approve` | POST | user | 临时令牌 | 空 | 401、403 越权批准 |

### 2.4 设备管理

| 端点 | 方法 | 身份 | 请求字段 | 成功返回 | 主要失败 |
|---|---|---|---|---|---|
| `/api/devices` | GET | user | 无 | 设备列表 | 401 |
| `/api/devices/bind` | POST | user | 设备 code | 绑定结果 | 404 设备不在线、403 已被他人绑定、422 |
| `/api/devices/bind-aux` | POST | user | 设备 code | 绑定结果 | 同上 |
| `/api/devices/{code}/unbind` | POST | user | 无 | 空 | 404、403 非本人设备 |
| `/api/connect/code` | POST | user | 设备 code | 连接凭据 | 404、403 |

### 2.5 远控与电源

| 端点 | 方法 | 身份 | 请求字段 | 成功返回 | 主要失败 |
|---|---|---|---|---|---|
| `/api/devices/{code}/power` | POST | user / guest | `action`（枚举见下） | 空 | 404、403、**422 action 非枚举** |
| `/api/devices/{code}/wol` | POST | user / guest | 无 | 空 | 404、403、422 设备不支持 |
| `/api/remote/qr` | POST | user / guest | 设备 code | 远控凭据 | 404、403 |
| `/api/agent/qr` | POST | 设备密钥 | `code`、`secret` | 被控端凭据 | 401 密钥错 |

`power` 的 `action` 只接受七个值：`on`、`forceoff`、`shutdown`、`restart`、`sleep`、`lock`、`logoff`。其他任何值一律 422，不做归一化容错。

### 2.6 文件

| 端点 | 方法 | 身份 | 请求字段 | 成功返回 | 主要失败 |
|---|---|---|---|---|---|
| `/api/files/upload` | POST | user / guest | 文件内容 | 文件 id | 403、422 超限、429 |
| `/api/agent/files` | POST | 设备密钥 | 文件内容 | 文件 id | 401 密钥错、422 |
| `/api/files/{fid}` | GET | user / guest | `key` 查询参数 | 文件流 | 404 不存在、403 key 不匹配 |

**[待核]** `key` 的语义：是文件级访问密钥还是签名，有效期多长。

## 三，WebSocket 帧

两条通道，鉴权方式不同：`/ws/agent` 用设备密钥，`/ws/control` 用账号或访客令牌。

### 3.1 `/ws/agent` 下行（服务端 → 被控端）

| 帧 | 字段 | 触发条件 |
|---|---|---|
| `hello` | `temp_pwd`、`owner`、`name`、`code`、`enable_code_login` | 连接建立后立即下发 |
| `pwd` | 新密码 | 账号侧改临时密码 |
| `bind` | 绑定信息 | 账号侧发起绑定 |
| `start` | 无 | 控制端发起远控 |
| `stop` | 无 | 控制端结束远控 |
| `input` | `move` / `wheel` / `down` / `up` | 控制端鼠标操作 |
| `key` | 按键 | 控制端键盘操作 |
| `text` | 文本 | 控制端粘贴 |
| `quality` | 画质参数 | 控制端调画质 |
| `clip` | 剪贴板内容 | 剪贴板同步 |
| `file` | 文件引用 | 控制端传文件 |
| `power` | `action` | 电源操作 |
| `wol` | 无 | 唤醒 |
| `error` | `code`、`message` | 服务端处理失败 |

### 3.2 `/ws/agent` 上行（被控端 → 服务端）

| 帧 | 字段 | 触发条件 |
|---|---|---|
| `frame` | `data`、`w`、`h` | 每帧截屏 |
| `status` | `name`、`os`、`mac`、`user` | 定时上报或状态变化 |
| `notice` | 内容 | 被控端提示 |
| `clip` | 剪贴板内容 | 剪贴板变化 |
| `power_result` | 结果 | 电源操作完成 |
| `file_out` | 文件引用 | 传文件 |
| `rotate` | 方向 | 屏幕方向变化 |

### 3.3 `/ws/control` 下行（服务端 → 控制端）

| 帧 | 字段 | 触发条件 |
|---|---|---|
| `ready` | `device` | 远控通道就绪 |
| `frame` | 帧数据 | 被控端发来帧 |
| `clip` | 剪贴板内容 | 被控端剪贴板变化 |
| `notice` | 内容 | 被控端提示 |
| `power_result` | 结果 | 电源操作完成 |
| `file_out` | 文件引用 | 被控端传文件 |
| `offline` | 设备 code | 被控端断开 |
| `error` | `code`、`message` | 服务端处理失败 |

### 3.4 `/ws/control` 上行（控制端 → 服务端）

白名单八个帧，且只接受这八个：`input`、`key`、`text`、`quality`、`clip`、`file`、`ping`、`power`。

白名单外的帧一律丢弃并回 `error`，不静默忽略。

## 四，错误语义

客户端必须能区分这五类，不能统一当「请求失败」处理：

| 状态码 | 语义 | 客户端应有的反应 |
|---|---|---|
| 401 | 身份无效或密码错 | 重新认证，不清空本地数据 |
| 403 | 身份有效但无权限（越权、非本人设备、key 不匹配） | 不重试，提示权限不足 |
| 404 | 目标不存在或设备不在线 | 视作可恢复，提示「设备离线」并允许重连 |
| 422 | 字段校验失败（缺字段、枚举越界、超限） | 不重试，报文本身有问题 |
| 429 | 限流 | 按提示等待后重试，不立即重发 |
| 503 | 服务端能力未接（如验证码网关未配置） | 提示功能不可用，不重试 |

404 与 401 的区分要特别注意：**设备不在线是 404，密码错是 401**。把离线设备报成 401 会让客户端误清登录态。
