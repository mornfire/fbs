# 静默失效目录

按「在哪一层失效」归类。每一条都不是设想，是撞过的。写作目的：让下一次能提前认出形状。

判定口径沿用验收清单：`PASS / FAIL / UNDECIDABLE / NOT_RUN` 四态，未测不得记成通过。

---

## A. 执行层：到底跑了没

**A1 预算耗尽伪装成空结果**
接口返回 `open=0 backlog=27`。返回值本身完全正常，被读成「没有更多了」。
为什么静默：正常返回值与「取完了」同形，差别只在 backlog 字段，而它通常没人看。
判据：`backlog > 0 且 open == 0` 即覆盖度不完整，判 UNDECIDABLE。

**A2 计划任务未运行但状态是 Ready**
任务设成「仅用户登录时运行」，会话锁定后永不触发，任务状态仍显示 Ready。
为什么静默：状态字段描述的是「已注册」，不是「在跑」。
判据：产物 mtime 必须落在本次窗口内；超过两个周期无产物即告警。

**A3 命令成功但参数被截断**
PowerShell 5.1 会吃掉传给原生程序的内层双引号，命令执行了，但参数只剩前半段，退出码 0。
为什么静默：程序认为参数合法，处理了它收到的部分。
判据：参数必须回显到回执里，做一次包含性校验。

---

## B. 产物层：东西有没有落地

**B1 零字节产物**
文件生成了，字节数为 0。只查「文件存在」会放过。
判据：逐级判定，`存在 → bytes > 0 → 哈希一致`，任何一步不过即停。

**B2 回执没有唯一 id**
发布接口返回空、无 id、无报错文本，流程当成成功。实际什么都没发出去。
为什么静默：没有错误信号，只有「没有成功信号」。
判据：回执必须带唯一 id，缺 id 即判未送达并告警。

**B3 产物在，但无人读**
报告生成了，下游没有任何环节消费它。产物存在变成了一种自我安慰。
判据：交付层要有独立的「已消费」信号；缺信号记 UNDECIDABLE，不记成功。

---

## C. 判定层：测了没测到

**C1 空内容当成零**
模型返回 HTTP 200、`content` 为空、`finish_reason=stop`，报告渲染成「未检出冲突」。
为什么静默：进程正常、规则没变、退出码 0，三层全绿。
判据：输出不可解析即 UNDECIDABLE；零结果必须附带覆盖度。

**C2 覆盖度缺失被并入通过**
报告只写「通过 100 条」，实际是 60 条验过加 40 条未测。
判据：未测必须单列，且落在分母之外的单独立账。

**C3 判定对、渲染错**
检测器判了 FAIL，报告却把那条归进「未检出」分组。内部账与对外账不一致。
判据：渲染层独立断言——比较「判定结果分布」与「报告里写出的分布」，计数不一致即 FAIL。

---

## D. 状态层：记忆与幂等

**D1 状态只存在对话里**
上下文一压缩，状态丢失，任务被重跑并产生重复副作用。
判据：状态必须落盘并带版本号；关键决定写进可恢复的记录，不进对话。

**D2 幂等键绑任务 ID**
同一任务换了内容，键没变，拿到了上一次的结果。
判据：幂等键绑内容哈希；重放检测放在写入之前。

**D3 索引行号错位产生假最新**
淘汰旧行时删行而不是打墓碑，行号整体错位，下一次读把下一条当上一条。
判据：索引视为派生物，可从日志全量重建；淘汰打墓碑不删行。

---

## E. 度量层：指标会骗人

**E1 受控变化让指标变好**
MP3 64k 的高频能量比原文件还高，因为编码器加了抖动。压缩让质量下降，指标却上升。
判据：方向性指标要配一个反向指标交叉验证。

**E2 均值被单条拉偏**
点赞均值 1250，最高 10987，中位数远低于均值——一张爆款撑着其余常态。
判据：用分位（P90/P50）而不是均值与标准差。

**E3 自愈让指纹复原**
用「下游状态是否变化」判断有没有干活，自愈或回滚会让指纹回到原值，活干过却判成没干。
判据：指纹之外加「本次是否产生了写入记录」的独立信号。

---

## 用法

做负控时，优先挑 `caught=false` 的那几条——它们是真实漏网的形状。每一条都应该能变成一个必败臂，期望值写死为 `FAIL`，判不出来即检测器坏了。

不要把 `UNDECIDABLE` 和 `FAIL` 混用：前者是「测了但判不了」，后者是「测了且不合格」。混用会把检测器故障伪装成样本问题。
