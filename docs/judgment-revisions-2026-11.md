# 判据设计的十四条外部修订（2026-11-07 至 11-08）

这份文档只记录**别人指出、我们认可并已落地或待落地**的修订。每一条写明：问题、谁指出、状态、怎么验。

## 一、已改

### 1. 答案键与题面分离

问题：早期夹具文件把 `expected` 与 `_grading` 一起下发，数据可信度无法自证。

改法：题面生成器只输出台账与场景（`id / input / action` 三个字段），答案键单独存放。导出脚本带泄漏检查，命中字段名或判定值即中止。

验法：`tools/export_testpacks.py` 跑完，逐文件搜 `expected / assertions / prerequisite_facts / _grading` 与四个判定值，命中数为 0。

### 2. 答案键生成器不依赖项目模块

问题：拆成独立脚本仍 `import` 同一份工具模块，依赖关系一比还是共享代码路径。（榫卯）

改法：`tools/make_keys_stdlib.py` 只依赖 `io / json / os`，九套夹具的键由它重新生成。

验法：该文件 import 列表里无项目模块；进程级检查另见第 6 条。

### 3. 必要集与签发集分权

问题：若「哪些字段是判定前提」由签发方维护，必要集会缩到刚好覆盖已签字段，UNDECIDABLE 永不出现。（屎山工程师）

改法：必要性清单由判定需求方冻结，`signed_fields` 由签发方产出；两清单不一致时落 UNKNOWN，不落通过也不落判不了。

### 4. 知情边界拆三态

问题：原来只有「有记录 / 无记录」两态，把「有记录但不含该角色」和「无记录」混成一个。（小花花）

改法：`known_by` 非空且不含该角色 → 违规；`known_by` 为空 → 判不了；有来源但记载不清 → 另记一类。

### 5. 补丁必须配必失败样本

问题：判据改动只跑公共哨兵集，粒度不到「一条判据配一条构造错样本」。（WorkBuddy）

改法：每条判据改动必须同时入库一条构造错样本；过两道门才算补丁——新判据抓得住、旧判据抓不住。

## 二、待改

### 6. 失败域要按进程核，不按目录核

问题：`import` 检查只是代理指标。两边若连同一个数据库、同一张表、同一把锁，零 import 也共享失败域。（榫卯）

待改：expected 生成与业务执行分两个进程跑，记录各自打开的文件句柄、数据库连接与锁对象，取交集；交集为空才算分开。

### 7. 判据顺序效应需要单独实验

问题：A/B 两版同时撤掉断言清单与前置事实清单，两个变量一起动，归因不到顺序。（凯瑞）

待改：固定其余全部字段，只交换两条规则的先后；同模型重复三次；逐格混淆矩阵公开。

### 8. 阈值要绑样本量

问题：0.7 的阈值是常数，12 格下置信区间宽到能让两处分歧跨过它，门槛等于随机触发。（Pearl）

待改：阈值写成 n 的函数，或在报告里同时给出「达到该阈值所需的最少格数」，不满足则不下结论。

### 9. 锚池要轮换

问题：反复重标有练习效应，固定锚池会高估一致性。（Pearl）

待改：锚池轮换，用重叠样本估漂移。

### 10. 合格参照臂

问题：只有必败臂时，两版都低于合格线，比较器照样排得出名次。（Yerik）

待改：加入已知达标的参照物，每轮同跑，得分落在历史容差带外即判比较器漂移。

### 11. 覆盖度与回退计数

问题：视频侧掩码若每镜各框一次，会把「位置变了」与「人变了」混在一起。（WorkBuddy）

待改：首镜框一次，下游按上一帧跟踪，仅在跟踪失败时回退重新检测；回退次数单列一列，作为健康读数。

### 12. 支撑关系用枚举

问题：`support_relation` 若为自由文本，「支撑 / 佐证 / 呼应」会被当成三种关系，跨样本聚合并不起来。（凯瑞）

待改：固定枚举 + 版本号；错表、错时段另记为负控错误类型，与关系类型分开。

### 13. 清单侧负控

问题：判据侧的负控有了，外部清单本身从没被反过来验过。（Hark）

待改：删一条必要项看能否发现漏检；加一条伪项看会不会滥收。两臂分开测。

### 14. 弃权作为总因的重述

问题：六条结论彼此独立表述，缺一个统一解释。（执）

看法：把「信息不足时不弃权」当成总因——一致性对措辞敏感、对样本量敏感、门槛随机触发，都是它的表现。修法因此收敛为一条：先让弃权成为可行选项，其余指标才有意义。

## 三、口径提醒

本文档里的「已改」指代码或文档已落地，不指效果已验证。第 1、2 条的效果验证是结构性的（搜不到答案、import 列表为空）；第 3、4、5 条尚无用例覆盖。

对外引用时请一并说明：这些修订来自同行公开讨论，不是独立评审。

## 四、第二批修订（11-08 晚，来自公开讨论）

### 15. 分箱方案也要事前冻结

问题：ECE / MCE / Brier 这类指标基于分箱，分箱数与边界是自由参数，会改变读数。（小清新）

改法：分箱方案与阈值同级处理——事前冻结，写进报告抬头的可复算区；换方案则作废重算，不允许事后挑好看的一版。

### 16. 复核挑选规则预注册

问题：复核名额有限，若谁被复核由人临时挑，覆盖率再高也可能是看完结果后挑的。（执）

改法：挑选规则事前写死；覆盖率低于阈值时不引用比率，同时报绝对值——小基数下比率噪声大，报 3/5 比报 60% 更可信。

### 17. UNJUDGED 拆两类

问题：把「判不了」与「没机会判」混在一个桶里，剔除行为无法解释。（Jasper）

改法：拆成 undecidable（样本在、证据不足）与 unavailable（数据未到、窗口未闭合）。前者剔除要单独披露剔除率，后者剔除属正常流程。

### 18. 回读要换通道

问题：回读走同一接口的返回，只能证明接口自洽，证明不了对端真的落地。（shibin / 小硕）

改法：回读走另一个进程、另一把凭据，或直接从存储层读；同通道回读只作辅助信号。

### 19. 必红孪生样本构造不出即挂起

问题：一条从来没有红过的判据，与一条坏掉的判据在监控上同形。（wbstella）

改法：每条判据配一条必须判红的孪生样本；构造不出来就把该判据标为失效并挂起，不算通过。构造不出本身是结论。

### 20. 负控入口打点

问题：上游过滤器可能把负样本提前丢掉，脚本全绿证明的是过滤器在拦。（wbstella / 流萤）

改法：负控样本带固定标记进入流水线，标记未出现即说明它没到判据侧，红与不红都不计入。

### 21. 空跑批次走同一入口

问题：为跑空跑另做一个简化入口，红了只证明简化路径的矛盾。（写手）

改法：空跑批次与真批次共用入口与装配路径；这类红单独归类为「判据自相矛盾」，不并入判据判错。

### 22. 弃权率不能单向读

问题：弃权率高既可能是覆盖不足，也可能是守住了边界，单看比率分不开。（执）

改法：同时报弃权原因分布（缺事实 / 缺记录 / 记录矛盾 / 不可解析）与「弃权后复核为真问题」的比例，后者需配覆盖率。

### 23. 分层三数同批冻结

问题：边界档占比若事后按结果划，α 一低就把难例挪进边界档，解释永远成立。（FTC）

改法：分层框先落清单（哪几件进可判定档、哪几件进边界档），签字时点数，算完不再动。

### 24. 作废记录双计

问题：按事件计会少记原因码，按码计会虚高。（Pearl）

改法：事件数与每事件挂码数分布同时记；另报多因事件占比——它高说明作废流程没收敛。
