# 交付验收清单（v1）

面向「无人值守执行 + 需要事后核对」的交付场景。这份清单不是理论，每一条后面都标注了我们踩过的对应事故。

---

## 一、判定顺序：任何一步不过就停

```
退出码（仅参考信号）
  → 产物存在
    → 字节数非零
      → 哈希与回执一致
        → 契约字段齐全
          → 覆盖度完整
            → 才允许判 PASS
```

**为什么退出码只作参考**：我们遇到过渲染器正常退出、文件也生成了，但字节数为 0。只看退出码或只看"文件存在"都会放过。

**事故**：`exit 0 + 产物存在 + 0 字节`，被旧判据判为通过。

---

## 二、三态判定，不要二值

| 判定 | 含义 | 计入分母 |
|---|---|---|
| `PASS` | 检查跑了，且通过 | 是 |
| `FAIL` | 检查跑了，未通过 | 是 |
| `UNDECIDABLE` | 检查跑了，但无法判定（缺字段、输出不可解析） | **否** |
| `NOT_RUN` | 检查根本没跑 | **否** |

**关键**：`NOT_RUN` 与 `UNDECIDABLE` 必须与 `PASS` 分列。把"没测"记成"通过"是最常见、也最难发现的静默失败。

**事故**：模型 HTTP 200、`content` 为空、`finish_reason=stop`，报告渲染成"未检出冲突"。进程正常、规则没变、退出码 0，三层全绿，但那一层根本没在测。

---

## 三、分母：用「应检单元」，不用总量

- 视频：按镜头对／字幕条／音轨段计，**不按帧数**（长镜头会稀释问题）。
- 文稿：按章节／段落计，不按字数。
- 接口：按端点 × 场景计，不按请求数。

**冻结规则**：分母定义必须与判据版本一起冻结，并记录**冻结时刻**。判据版本号不变但切分规则在实现里被改过一行的情形，我们遇到过——版本号骗过了比对。

---

## 四、环境集冻结（版本回执）

可复现的读数必须携带能改变它的最小环境集。我们的四项：

1. 渲染器／执行器版本
2. 编码器与压缩参数版本
3. 字体与色彩配置
4. 区域与语言设置

**为什么要这一条**：同一输入、同一内容，换机器后哈希不同——根因是字体回退到不同字形集。可复算、正确，但不可移植。

**规则**：读数依赖的环境项若不在上述集合内，一律标为 `local-only`，不得作为判据属性发布。

---

## 五、双哈希：判据版本 vs 实现版本

| 字段 | 覆盖范围 | 变更后果 |
|---|---|---|
| `criteria_digest` | 判据定义本身（含参考样本） | 必须重跑，历史不可比 |
| `implementation_hash` | 切分规则、归一化实现 | 判为"语义等价但实现变更"，历史保留可比 |

只用一个哈希的话，重构会让全部历史数据失效，而重构通常是语义等价的。

---

## 六、负控：必败集合，且分层

每个判据都要有对应的负控臂，且**分层统计**：

- 规则层负控：n/n
- 语义层负控：n/n
- 交接层负控：n/n

**分层的原因**：按臂算总分会被规则层的高覆盖率拉高。我们的语义层在事故之前是**零负控覆盖**——它一直是绿的，因为它从没被负样本打过。

必败样本至少三类：

1. 空结果伪装成真零（未测 → 判 PASS）
2. 产物存在但内容为空
3. 证据被改写而非原文引用（逐字匹配应判 FAIL）

---

## 七、静默失败模式清单（我们的真实记录）

| # | 模式 | 表现 | 判据修正 |
|---|---|---|---|
| 1 | 空内容 + 正常结束 | HTTP 200，content 空，finish_reason=stop | 覆盖度不完整 → UNDECIDABLE |
| 2 | 零字节产物 | 文件存在但 bytes=0 | 逐级判定，字节非零才继续 |
| 3 | 锚点与业务同源 | 业务停摆时锚点也不写，对账显示"一致" | 锚点独立进程、独立重试 |
| 4 | 状态只存对话 | 上下文压缩后状态丢失，任务重跑 | 状态落盘 + 版本号 |
| 5 | 换机器哈希变 | 字体回退导致产物哈希不同 | 环境集冻结进回执 |
| 6 | 扫描预算耗尽 | 返回 `open=0 backlog=N`，被读成"没有更多" | backlog>0 即覆盖度不完整 |

---

## 八、可选的第三方复跑

如果交付需要外部核对，给出三样东西即可让对方独立判定：

1. 判据版本（`criteria_digest`）与冻结时刻
2. 一份必败样本 + 一份必绿对照
3. 回执字段说明（含覆盖度字段）

对方跑完只需回一份**差集**：`check_id / expected / actual / verdict`，缺行记 `MISSING`，不记"一致"。
